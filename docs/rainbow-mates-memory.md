# Rainbow Mates 角色记忆架构

**方案更新于 2026-11-25。** 默认内置向量模型确定为 BGE-M3 ONNX INT8。模型已下载并完成本机 Python CPU 编码验证。本文与架构图描述待实施设计，Electron 运行时的内存、延迟和 Rainbow 数据集上的召回效果列入接入验收。

## 已确定的组合

| 职责 | 方案与目的 |
| --- | --- |
| 理解、抽取、评分和整合 | 每角色独立记忆线程，复用该角色当前配置的 Codex／DeepSeek 模型与档位 |
| 语义编码 | 应用内置 BGE-M3 ONNX INT8，通过 ONNX Runtime Node 在本机执行。所有角色复用同一个编码进程与权重 |
| 检索与存储 | SQLite 保存角色记忆、1024 维稠密向量、来源、计分、版本与队列。向量余弦相似度为召回主通道，FTS5/BM25 与字段等值匹配提供补充候选 |
| 强化与淡忘 | 新记忆强度 100、次数 1。有效使用后次数加 1、恢复 100 分并重新起算。半衰期为 `min(max(I-C+N,1),10)^2` 天，最大 100 天。强度低于 20 停止召回，保留时长随曲线变化 |
| 任务接续 | 任务记录保存目标、进度和产物的检查点。角色可以把亲历的任务提炼为自己的经验 |
| 后台整理 | 平时吸收和修订，空闲时合批归纳，按各条目的有效状态清理派生正文与向量 |

## 模型资源与运行方式

基础模型由 BAAI 发布，量化产物采用 `gpahal/bge-m3-onnx-int8`。本次下载固定提交 `2b34e84df040034d4b9eabb62383a87c18955822`，权重文件 SHA-256 为 `16de7ea1146ca427e14938ec3e9abfdcaff0e6ac76434cd693ac35d761250bcb`。模型卡说明会同时输出 dense、sparse 和 ColBERT 表示，本方案使用归一化的 1024 维 dense 表示做主检索。发布还需固定分词器和运行时版本，并验证默认导出的算子可在目标平台执行。

模型和分词器随安装包附带。应用中提供内部 `encode(texts)` 接口，返回编码器版本、维度和 Float32 向量。独立编码进程在首次请求时加载权重，所有角色共用一次加载，按小批次处理。前台查询优先，后台新记忆编码与整理排在其后。初始采用 CPU 和短文本批次，支持空闲后退出进程释放内存。空闲回收时间作为后续性能调优参数。

**下载与功能验证。** 资源保存在 `/Users/korilin/Library/Caches/rainbow-mates/models/bge-m3-onnx-int8/2b34e84df040034d4b9eabb62383a87c18955822/`。文件尺寸逐项核验，三个大文件与发布方 SHA-256 对照，其他文件记录本地摘要，结果写入 `rainbow-model-manifest.json`。用现成 Python ONNX Runtime 1.19.2、CPU 双计算线程、batch 1、token 上限 128 测试 5 条中英文短句，输出为归一化的 1024 维 `dense_vecs`。模型及分词器加载约 1.22 秒，逐条编码约 29–59 毫秒，进程峰值 RSS 1622.3 MiB，约 1.58 GiB，包含模型初始化。这里只做功能验证，完整查询还包含检索和上下文处理，Electron Node 的峰值与常驻内存另测。详细结果保存在资源目录的 `rainbow-encoding-smoke.json`。

记忆先由角色模型提炼成自包含的短条目。较长经历按语义分段，共用父记忆 ID。初版每片段最多 1024 token，每批最多 2 个片段，属于控制内存与延迟的初始预算。必要条件和适用版本随片段保留。每段编码，检索后按父记忆去重和计数。编码失败会留下待重试条目，日志显示索引状态。

## 谁决定记什么

角色是持续存在的人。它的身份由 Rainbow Mates 的 `roleId` 标识，模型和 Codex／DSH 线程是它当前使用的运行环境。角色读到消息以后，自己判断要不要记、哪里值得留下、后来要不要修正或淡忘。用户消息是角色看到的内容，与普通聊天用同一入口。应用没有逐条编辑、固定、忘掉、恢复记忆的用户操作，也不对聊天文本执行这样的命令。

聊天和任务线程提交角色实际接触的事件、本轮用到的记忆，以及要回想的问题。独立的记忆线程用该角色自己的模型进行抽取、评分、合并与按意思补查。应用负责执行查询、校验证据、持久化、计时与一致性。应用从本轮授权推导角色归属。

角色只有一套记忆，内容包括它听过的话、做过的事、知道的结论、与用户的交互和约定。同一角色在任何会话都读自己的这套记忆。经历正文可以写「在需求讨论里，我跑过单测，结果通过」。记忆条目不存会话 ID，检索也不按会话 ID 分桶或过滤。证据用消息、交接或工具结果的来源引用追溯，其访问仍由应用校验。

角色只能从自己实际接触到的内容形成记忆。发送、排队或入会本身只记录事件。只有消息、引用、交接材料或工具输出实际交给这个角色处理后，才能作为其记忆来源。新成员可以使用自己在其他场合已经形成的记忆。当前会话以前的内容经过介绍、引用或交接后，才进入它的经历。离开再回来的角色保有自己原来仍有效的记忆。

## 应用身份、任务和运行时

| 对象 | 归属 | 持久化 |
| --- | --- | --- |
| 角色设定与本机用户身份 | `roleId` 与 `localProfileId` 分别标识角色和用户。名字、头像、模型是可改配置 | 现有工作区配置及本机个人资料 |
| 角色记忆 | `roleId + localProfileId`，同一角色在各会话读取。经历和知识采用同一生命周期 | 本机 `memory.sqlite` |
| 当前任务状态 | `taskId` 标识任务，任务归属、分派和交付记录控制访问。一次执行使用现有的工作消息 ID 作为尝试标识 | 原任务记录中的版本化检查点 |
| 角色记忆线程 | `roleId + localProfileId`。逻辑处理队列持久，模型上下文按批次创建 | 持久化事件队列、消费水位和操作记录。模型调用可重建 |
| Codex／DSH 原生线程 | 原生线程 ID 关联当前运行时的一段上下文 | 仅供续接的运行时映射，可以随时更换 |

Electron 主进程根据本轮实际接收者建立授权上下文，校验角色、来源及任务授权。数据库查询或写入只接受应用确定的角色归属。模型可给查询词、操作和来源 ID，工具参数不能覆盖归属。本地数据目录承担当前安装的边界。区分来源说话者与事实所指的人。角色对自己人设的描述来自角色配置，角色的推测或转述无法作为关于用户的可靠证据。会话 ID 仅供平台分发、交付和维护原生线程映射。

沿用现有运行时适配器。Codex 继续走 app-server 的 stdio JSON-RPC，DSH 继续走 headless。聊天线程、任务线程和记忆线程都可以通过同一适配层调用角色当前配置的模型，使用各自的上下文。记忆处理只拿本批来源、已授权的旧记忆候选和记忆操作协议。兼容的聊天和任务运行时可调用本轮绑定的只读查询工具。

**memory_search 由 Rainbow Mates 实现和提供。** 工具接口通过应用管理的 MCP 服务接入 Codex 和 DSH，绑定发起者的角色身份。模型提交 `{ query }` 及可选数量预算，平台决定允许访问的范围，编码查询、检索并返回记忆 ID、版本、正文、来源和待核实说明。只读表示此工具的职责是读取已有条目。查询结束后，实际采用回执负责触发强化，独立记忆线程的结构化操作负责写入和修订。后续实现需验收两个运行时的工具注册、调用、超时和结果回传。

| 时机 | 接入动作 |
| --- | --- |
| Rainbow 启动 | 主进程创建记忆服务、队列和本机 Streamable HTTP MCP 端点。端点准备好后，运行时可以注册连接。编码模型在首个编码请求时加载 |
| 启动角色运行时之前 | 应用生成绑定该角色与调用线程类型的连接上下文。Codex app-server 的本次启动配置增加 `mcp_servers.rainbow_memory.url`。DSH 本次 headless 配置增加 `@deepseek-ai/dsh-mcp-client`，设置服务名、传输与端点。复用项目已有的 Computer MCP 接入模式 |
| 开始模型轮次之前 | 运行时进行 MCP 初始化与 `tools/list`，将工具定义交给模型。连接成功后创建线程并执行作业。已运行的原生进程在受控重建时接入新配置 |
| 执行中决定回想 | 模型发出 `tools/call`。Rainbow 绑定角色，执行编码、检索和证据核对，将正文送回原工具调用。需要复杂解释时安排独立记忆作业 |
| 重连或退出 | 原生进程重启后重新连接并读工具列表，来源和记忆水位继续持久保存。应用退出时关闭服务与模型进程 |

记忆线程自身进行补查时，工具直接调用底层编码和检索，基于当前作业完成筛选。调用上下文区分聊天、任务和记忆作业，避免记忆作业再次等待自己的队列。写入提案作为结构化作业结果交给应用校验。MCP 接入、编码进程和存储适配均是待开发模块。

## 独立记忆线程

**每个角色有常驻的逻辑队列，模型线程按批次短开。** 聊天和任务都给同一个队列交事件，可以同时查已提交的记忆。一次增量或空闲整理用一个短模型上下文，附带角色设定与记忆操作协议。记忆作业只向模型提供本次已接触来源、授权的记忆查询和类型化操作接口。应用可以复用运行时进程和连接来降低启动成本。角色换模型、应用重启或原生线程失效后，从 SQLite 的队列和水位接上。短模型上下文只传本批事件及相关旧记忆，可以把评分依据限定在可追溯的资料上，也能限制模型输入大小。

| 路径 | 谁负责 | 何时执行 |
| --- | --- | --- |
| 取回记忆 | 原问题先由内置编码器生成查询向量，应用按当前角色取向量候选并融合词法候选。必要时记忆线程理解问题、改写补查和整理冲突 | 用户轮次开始前、任务开始前，以及执行中调用查询工具时 |
| 采用已知记忆 | 聊天或任务提交使用回执。服务校验角色、版本和回执后，按公式立即提交强化 | 回复或操作结果提交时。算分直接执行，无需为单纯的强化再调用模型 |
| 从新经历学习 | 记忆线程使用角色配置的模型，把接触过的事件抽取为条目，与相关旧条目对照，返回跳过、新增、修订、合并、改分或忘记 | 发现可能影响后续回复的新信息时优先处理。其他候选可按角色合批。没有候选时，跳过模型调用 |
| 定期整理 | 同一个记忆线程归纳零散内容、重新评分、修订失效关系。应用核对旧版本，提交正文、索引和水位 | 平时增量更新。连续空闲 10 分钟且有待整理内容时可追加集中批次，模型整理初始预算为每角色每天一次 |

**跨会话何时可见。** 聊天回复可以先发布。角色在 A 接触新偏好后，记忆线程处理到当前事件水位并完成编码，正文与向量共同落库，再让 B 的下一轮执行召回。正在执行的任务可以查最新已提交版本。记忆处理超时或失败时，应用保留作业重试，明确记录失败状态，下一轮使用已提交版本和角色实际接触的有限未处理事件补充，完成编码后发布新索引。后台整理按条目版本提交，晚到结果重读最新条目后处理。每个角色按来源事件维护水位，应用单写入者提交。

**写入索引。** 来源校验后，把新经历编码，查该角色相似旧条目，再交给独立记忆线程抽取和比较。模型给出新增、合并、修订、降分、遗忘或跳过，以及重要性、复杂度、来源和旧条目版本。应用校验后对最终正文编码，将正文、向量、全文索引、计分和消费水位原子发布。内容更新先编码新正文，提交时校验旧版本；明确纠正事件可以先让旧事实失效，失败重试期间旧结论持续标为失效。只改重要性和次数时，直接更新计分。派生模型输出沿用其底层来源。

## 任务检查点

在现有任务对象上添加版本化 `checkpoint`。它记录当前目标、任务修订版本、执行尝试、完成步骤及其验证证据、未完成项、阻塞、下一步和附件引用。大型产物保留在已有文件或附件存储里，检查点写入引用和必要的校验信息。运行中的详细工具输出继续作为执行记录。一次尝试取消、运行时切换或应用重启后，按任务授权读取最后已提交的检查点。重建线程时只传当前任务要求、检查点和相关证据。

应用先复用现有的任务修订、依赖、已交付结果和交接数据。已确认副作用和状态不明的副作用单独标记。若中断时外部动作是否成功无法确定，接续先核对可观测状态，再决定是否重做。已交付的结果属于任务记录。角色可把亲历后觉得有用的工作经验整理到自己的记忆，保留检查点或交付消息作为来源。想起结论不会获得任务、文件或原始聊天的额外权限。

## 存储与写入

`Conversations.send` 保存平台消息和来源序号。运行时开始处理后，应用记录本轮实际交给该角色的消息、引用和交接材料。运行时返回给角色的工具结果同样作为来源。角色结合这些内容判断真实偏好、猜测、转述与虚构。收到公开消息的角色可各自形成记忆。工作经历和用户交互使用同一套写入接口。

聊天和任务提交类型化经历事件和使用回执。记忆线程每次写入判断包含操作、内容、来源、重要性、复杂度、适用时间及要修订的旧条目版本。应用校验身份、来源可见性、分值范围、版本和事件顺序。角色静默处理公开消息也可以提交经历事件。聊天回复和记忆操作各自校验。

记忆存于应用用户数据目录的 `memory.sqlite`。采用 `node:sqlite`、WAL 和单写入者。保存正文条目、向量片段、来源关系、待处理事件、使用回执、版本和原生线程中曾注入的来源。1024 维 Float32 向量按 BLOB 存储，每片段纯向量约 4 KB，一万片段约 41 MB。内置编码器保持归一化规则一致。

初版按角色和有效状态从 SQLite 读取向量，在独立检索 worker 内计算精确余弦相似度并取 top-k。该精确计算是逐一比较语义向量。将其与错误码等字段的等值匹配分别记录。片段共用父条目的四个记忆量，返回候选按父 ID 合并。同一读事务或版本快照内取候选，发布前再校验，避免检索期间的失效结果混入。

正文、向量、全文索引和消费水位在同一 SQLite 事务中提交。使用回执用角色、父记忆和工作事件 ID 去重。重试确认已有提交，迟到操作按来源顺序及版本校验。想起某任务的经历时，原检查点和附件仍按任务授权读取。

## 证据与冲突判定

角色决定愿意留下什么。应用分别记录记忆的强度和证据状态。强度影响随时间淡忘及召回的优先级。证据状态取决于可核对的来源、有效时间、适用条件和冲突情况。模型对自己答案的置信度不改变这两项。原始会话记录依现有方式保存，长期检索索引只收角色选出的记忆。

每条记忆至少带上事实键、事实所指对象、来源说话者、来源事件或验证记录，以及时间与必要的适用范围。用户直接表达的个人偏好可作为偏好的证据。角色转述或猜测仅作线索。实际工具结果可证明该操作可观察到的结果，例如某版本运行了一条验证命令且退出码为 0。适用范围可能包括版本、分支或任务修订，结论不能越过证据范围。

| 处理时机 | 可核对的规则 |
| --- | --- |
| 记忆线程提出写入、修订或丢弃 | 用事实键匹配同一范围的条目，区分单值与多值。新增有依据的细节可修订同一记忆。明确纠正使旧值退出当前召回，以新证据建立新内容和计数。新的推测只作为线索。版本替代保留必要的失效关系和来源标识，派生旧正文按既定生命周期清理 |
| 准备本轮候选或执行中补查 | 先校验归属、来源和有效期，排除已失效项；根据适用范围将其余条目标为可用事实或待核实线索。已知旧运行时上下文持有已失效内容时，该线程下次使用前重建 |
| 仍有冲突 | 多个可能互斥的有效线索按同一事实键成组，只给角色必要的冲突说明和可用证据。角色可说明差异，或向用户确认。找不到足以判定的证据时允许暂不下结论 |
| 执行依赖旧结论的操作 | 风险依照当前操作及环境的可观测状态判断，按现有权限约束执行。影响事实的版本、工作区或任务修订有变化，以及操作后果难撤销时，依赖当前来源或检查点重新核对。旧的操作记忆不授予当前权限 |

起步用主进程的确定性规则和原因码表示上述状态。如一次测试的验证记录来自提交 A，在提交 B 只作为复测线索。用户明确说明自己已搬家时，当前住所只使用新信息。两条未解决的转述不会因为其中一条匹配分高就变成当前事实。本轮的候选解释可以记录条目 ID、判定原因和引用的来源 ID，随现有生命周期清理。

## 每轮怎么召回

1. 应用固定本轮的会话、角色、用户和来源序号。当前请求、明确送达给该角色的引用和任务检查点直接加入上下文。旧聊天、笔记和任务记录按实际送达的范围访问。
2. 用户原文连同必要的任务目标作为查询，交内置 BGE-M3 编码。先限定角色、有效状态和至少 20 分的强度，再取向量 top-20，得到记忆 ID 和相似度。按这些 ID 读取库里的正文、来源与适用条件。正文在写入时随向量保存，查询通过向量定位，再读取该正文。并行执行字段等值和 FTS5/BM25，按父记忆去重，按各路名次融合，核对来源、适用版本和有效期。以相关性为主，在相近结果中参考当前强度与重要性。初始向量候选 20、最终注入最多 12 条并受 token 预算限制，这些属于待实测的参数。新话题会生成新向量，必要时拆成少量子查询。
3. 聊天和任务调用 `memory_search` 时经过同一检索接口，查询必须对应已接触的目标或新线索。简单查询直接返回经校验的记忆，调用者在正常一轮中使用。复杂意图、候选含冲突或不足时，独立记忆线程用角色当前模型改写问题，编码后再次向量检索，并选择有来源的结果。初始补查至多两组查询。预算用尽时返回已有结果、待核实说明和缺少哪些线索。执行中同轮调用要分别在 Codex app-server 和 DSH headless 验证。
4. 聊天或任务线程拿到结果后继续原来的工作。角色实际用到某条记忆时，提交条目及版本、这轮怎么用到的、对应回复或任务结果引用。应用按本轮已送达的记忆版本校验。候选不足时，角色可以说明没想起来或请用户给线索。
5. 目标设计中，同角色跨会话使用一个串行聊天线程。每次输入携带来源和回复路由，输出回来源会话。**角色连续 4 小时没聊天，下次聊天时重建线程。** 占用、上下文超限或已撤回证据也可触发重建。新线程注入角色设定、相关记忆和实际接触的最近必要片段。任务线程各自从授权检查点接续，记忆线程按批次短开。三个线程分别使用原生 ID。

| 候选来源 | 输入和执行方式 | 能找到什么 |
| --- | --- | --- |
| 字段等值匹配 | 已知错误码、完整路径或 ID，应用按字段规则归一化后交给 SQLite 做相等比较。查索引这一步无需模型 | `SQLITE_BUSY` 命中归一化后的 `sqlite_busy`。查 `desktop/store.mjs` 可排除 `desktop/store.test.mjs` |
| 全文关键词 | 用 `Intl.Segmenter` 分词，SQLite FTS5 在记忆正文、别名和检索短句中查词，以 BM25 排序 | 适合问题和记忆有共同词或已收录的别名 |
| 向量主通道 | 同一个 BGE-M3 版本编码查询与正文，在当前角色范围内比较向量方向的余弦相似度 | 「几个任务同时保存失败」可以召回「单写入队列解决 SQLite 争抢写锁」的经验，中英文本也使用同一空间 |
| 独立记忆线程补查 | 角色模型理解意图，将复杂问题改写或拆成少量子查询，再编码并向量搜索。基于候选整合结果和冲突说明 | 需要把「那次」「后来怎么改的」结合当前已知线索理解时，查询可以更贴近实际经历 |

**编码器版本与恢复。** 向量记录编码器 ID、模型 revision、分词器与预处理版本、维度及正文版本。同一编码器对记忆和查询使用一致的预处理。角色切换 GPT／DeepSeek 时继续使用这些向量。编码器升级时在旁路建立新索引，待全部有效条目验证完成后切换，查询从同一版本取向量。旧索引按生命周期清理。编码失败显示记忆索引降级状态，继续用已准备好的合法候选，并保留作业重试。

**执行中的查询。** 第一次按任务目标准备上下文。工具返回 `SQLITE_BUSY` 时，任务线程可提交错误码、路径和「之前怎么解决的」，应用编码这组线索并融合字段候选。独立记忆线程在需要时补查或解释矛盾。结果返回本次工具调用，任务继续执行，实际采用后计一次使用。工作进度按 `taskId` 直接读取检查点。

## 四个记忆量与半衰期

| 记忆量 | 怎么取值 | 谁更新 |
| --- | --- | --- |
| 强度 `S` | 新条目和有效使用后从 100 起算。读取时按当前衰退曲线计算 | 应用按时间和事件计算 |
| 重要性 `I` | 整数 1–10。1–3 表示偶发细节，4–7 表示可影响后续理解或步骤，8–10 表示遗忘会显著影响约定、关系或决策 | 记忆线程参考 Generative Agents，以角色视角评分，提交证据与简短理由 |
| 复杂度 `C` | 整数 1–5。1 是单一事实或偏好，2 有一个条件或关联，3 有多个相关事实，4 有相互依赖的条件或步骤，5 是多段、多条件的连贯经历。按最终记忆内容和必要关联打分 | 记忆线程在写入、改写或合并后评估。有独立含义的事实可拆开，必须一起理解的条件留在同一条 |
| 召回次数 `N` | 新条目为 1。每次被角色实际采用后加 1。搜索命中、注入、浏览和整理只是候选或阅读事件 | 应用在收到有效使用回执后按事件去重更新 |

```text
平方基数 B = min(max(I - C + N, 1), 10)
半衰期 H（天） = B^2
当前强度 S = 本段起算强度 × 0.5^(本段经过天数 / H)
```

记忆强度的首段从 100 开始。平方基数限制为 1–10，半衰期范围为 1–100 天。重要性和召回次数越高，半衰期越长，达到 100 天后保持上限。其他条件相同，复杂度影响进入上限之前的衰退速度。以重要性 5、复杂度 2 为例，新条目 `N = 1` 时，半衰期 16 天。第一次实际使用后 `N = 2`，恢复 100 分并改为每 25 天减半。第二次使用后 `N = 3`，恢复 100 分并改为每 36 天减半。`N = 7` 时基数到 10，半衰期为 100 天。`N = 100` 时基数仍取 10，半衰期仍为 100 天。

召回次数继续累计，作为真实使用记录保留。达到上限后，每次实际使用仍将强度恢复为 100，并从使用时重新起算。以最大半衰期 100 天、起点 100 分且此后未使用为例，第 100 天为 50 分，第 200 天为 25 分，约第 232.2 天降到 20 分，之后退出召回。

| 发生的事 | 曲线如何更新 |
| --- | --- |
| 记忆被搜到或传入上下文 | 保持现有曲线。回执须说明此条如何影响回答或步骤；准确回答关于这条经历的问题也算一次使用 |
| 实际采用这条记忆 | 采用时重置到 100，从该次使用开始按 `N + 1` 对应的半衰期衰退。同一条记忆在同一聊天轮或任务工作事件最多计一次；重试和重复工具调用复用原事件 ID |
| 重要性变化，或内容修订后复杂度变化 | 先按旧曲线算出事件发生时的强度，再用这个强度接上新半衰期。改分保持次数不变。若同次事件也有有效使用，按最终参数重置到 100，并将次数加 1 |
| 后台将多条记忆合并 | 合并条目取来源计数的最大值作为次数起点，避免把同一经历的多种表述相加。当前强度取来源条目当前有效强度的最大值，接上重新评估的 I、C 和 H。保留来源关系和旧 ID 到新父 ID 的映射，使用回执继续按原事件去重 |
| 新证据完全推翻旧结论 | 退出旧版本的当前召回，按新事实计算内容、重要性和复杂度，新条目从 100 分、1 次开始 |

实现可存每段起点时间与分数，并在读取时计算有效强度。状态变更校验基准版本和事件时间，应用用同一事务提交计数、评分与曲线起点。普通记忆**低于 20 分退出召回**，自动注入和执行中补查都按这一规则执行。内容可以有自己的有效期，被更正或被角色主动遗忘时也可以提前退出。保留时间随每条记忆的曲线走。下次整理清理派生正文与索引，只保留必要的防重放关联。之后角色遇到新经历，仍可决定形成新记忆。

**一次性提醒与任务。** 角色接下定时提醒后，由任务状态和时间调度保证到期可以触发。实际发出后，关闭这次待办并立即退出待行动队列。记忆线程可以调低历史经历的重要性、重新提炼内容，或丢弃。次数很大时，降重要性未必能让强度快速跌破 20 分，所以完成状态必须独立生效。例子里「我提醒过你续费」可以留下来，它只证明提醒送达。

## 平时整理、空闲整理与上下文更新

- **平时整理。** 记忆线程随时处理符合条件的新经历，应用持续去重、写索引和维护版本。任务改期、事实纠正和用途变化由相关事件触发。单纯打分和合并后台数据时保留有效使用的定义。
- **每日空闲整理。** 角色连续 10 分钟空闲且有待整理内容时，应用安排一次集中整理，每个角色每天最多完成一次。纯去重、索引和已确定的生命周期清理按规则执行。需要归纳或取舍时，由该角色当前配置的模型处理该角色范围内的一批经历，沿用同一套记忆操作接口。常规聊天的优先级最高。持续忙或应用关闭则等下次有空，跳过的日期无需补跑。需要模型判断的集中整理以每角色每天最多一次为初始预算。
- **原生上下文更新。** 记录运行时已见过哪些记忆和来源。角色丢弃、改正或时间已失效的内容后，重新使用受影响原生线程前重建，并过滤相同的失效派生内容。清理派生记忆时保留原聊天、笔记或任务证据。进行中的任务继续从已发布的有效检查点接续，避免重做已有副作用的操作。

| --- | --- | --- |

| T1b | 来源队列、独立记忆线程、评分操作和原子发布 | A 轮学习后，B 轮能向量召回新偏好。同一模型的两个角色各自读取自己的记忆。模拟抽取、编码、写库各阶段失败和重启，验证重试去重、版本校验与水位。索引失败显示降级状态 |
| T2 | 统一角色聊天队列、实际接触的来源校验、独立任务检查点、交付及新旧线程注入 | 同角色 A/B/A 按序回复到原会话，相关经历可跨会话召回。4 小时规则、线程占用和重建仍接得上。排队但未交给角色的消息不能作为记忆来源。入场时没有自动导入旧内容，显式交接限于指定资料。其他角色不能读取该角色的私有记忆。暂停记忆整理或更换任务运行时，仍可从授权的检查点接续。模拟副作用成功但中途断联，恢复先核对且不盲目重放 |
| T3 | 中英向量检索、证据与衰退、执行中查询 | 对相同语义的中英改写、跨语言查询、没有相关记忆、同报错不同项目建验收集。报告 Recall@5 与 MRR，以及最终回答的误引用和弃权。与原始 BGE-M3 在相同预处理和测试集上对照，接受阈值根据实测确定。变更编码器时验证索引原子切换。工具返回新错误后能同轮补查 |
| T3b | 使用回执、计数和生命周期 | 曝光沿原曲线衰退。采用一次计数从 1 变 2、周期从 16 变 25。同一回执重放计数保持 2。改分保持强度连续。I=5、C=2 时，N=7 和 N=100 的半衰期均为 100 天。所有合法 I、C 下，N 很大时周期也最多 100 天，N 仍继续累计且实际使用仍重置强度。强度低于 20 停止召回，超过 180 天但有效且强度达标的条目仍能查到。待办完成立即退出待行动队列。清理同步删除各检索索引，后台整理保留来源和去重关系 |
